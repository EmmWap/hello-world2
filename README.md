Q- Outline why developers use version control (e.g., tracking changes, collaboration, rollback, accountability).  (AC1.1) 

A - Version control saves changes over time, saving every edit that was made with a timestamp. It allows you to look back to previous versions, see who has made specific changes and when they made them, giving accountability. It allows you to go back to previous versions or undo something that was done in a previous version. It uses branches, which take a section of a project and copy it for individuals to work on in isolation of the main project so that it does not affect the main project. When the individuals have finished the section they are working on, they can submit their work to be review and added to the main project. This means that multiple developers can collaborate on the same project. For developers, tracking all changes and seeing who has made what changes gives a clear picture of workflow, making it easier to identify bugs and see how people are contributing to a project. Version control projects are usually linked to a remote server which means data is backed up remotely. In the event that an individual's computer crashes or break, they can get their work back easily.  

Q- Explain ways to use version control in a small Python project (e.g., commit often, meaningful messages, branches for features, pull requests for review). (AC1.2) 

A- In a Python project, you could get each developer to work on specific areas of the code and use branches to do this. The should commit their work after each important step they do e.g. write a function, fix a bug etc. They should make sure to write a suitable message with each commit that clearly states the change that was made for other developers to understand quickly (e.g. instead of writing 'function added', write 'function added to calculate the total cost'). Once a section is completed a developer can send a pull request for their work to be reviewed and then merged with the main project.
